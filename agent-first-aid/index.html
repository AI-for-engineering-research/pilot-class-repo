Agent First Aid

A no-judgment field guide for when you are stuck. New to terminals, GitHub, Python, coding agents, Markdown, VS Code, WSL, or Codespaces? This page is for you. It will not teach you everything about computing — it helps you take one safe next step with an AI assistant.

When you are stuck, your first job is not to know the answer. Your first job is to ask a useful next question.

START The Agent First Aid loop

Almost every fix in this course is the same five-move loop. When in doubt, run the loop.

01
State
Say what you were trying to do — out loud or to the agent.
02
Inspect
Paste exactly what happened. Errors are data, not failure.
03
One small step
Ask for a single reversible next action — not the whole fix.
04

Check whether the step actually worked.
05

Note what you changed so future-you can retrace it.

01 I don't know where to type this

The instruction is clear; you just can't tell which window it belongs in. Totally normal — the same words mean different places.

"Ask the model" → a chat box (browser or the chat panel in your agent tool).
"Edit the file" → the GitHub web editor, VS Code, or Codespaces.
"Run this command" → a terminal, not a chat box.
"Commit your changes" → the GitHub web UI, or a git command in a terminal.
"Run the notebook cell" → inside the Jupyter / notebook interface.
"Where does this go?" prompt
I was told to do this:

[PASTE INSTRUCTION]

I do not know where to do it: browser, GitHub, VS Code, terminal, WSL, Codespaces, or notebook. Please tell me where this action belongs, what I should click or type, and what I should expect to see if it works.
Real exchangegenerated live with a coding agent
Student

My TA told me: "clone the repo, create a branch, install dependencies, run the local server, commit your changes, and open a pull request." I genuinely don't know where I'm supposed to do any of this. Is this in the browser? GitHub? The black terminal window? Help.

Agent

Welcome — this is a really common place to feel lost, and you're not doing anything wrong. The short answer: almost all of it happens in Codespaces (a full coding environment that runs in your browser), and most of the commands go in the terminal (that black window at the bottom).

Let's just do the very first step: open your Codespace.

  1. Go to your repo on GitHub (the website) in your browser.
  2. Click the green < > Code button.
  3. Pick the Codespaces tab, then click Create codespace on main.

What to expect: a new browser tab opens with something that looks like VS Code. It takes a minute or two to load. When it's ready, you'll see your project files on the left.

Here's the nice part: opening a Codespace usually clones the repo for you, so the first item on your TA's list is already handled.

Once it's loaded, tell me what you see and we'll create your branch together. You've got this!

02 I got an error message

An error is the computer telling you exactly what it tripped on. It is information, not a verdict on you.

One rule that fixes most error questions: paste the full error, not a paraphrase. The exact text usually contains the answer.

Error prompt
Here is the command or action I tried:

[COMMAND OR ACTION]

Here is the full error message:

[PASTE ERROR]

Please do four things:
1. Explain the error in plain English.
2. Identify the most likely cause.
3. Give me one safe next step.
4. Tell me how to check whether the problem is fixed.
🔒
Do not paste secrets

Never paste passwords, API keys, private tokens, unpublished sensitive data, or human-subject data into a public AI assistant. If an error contains a secret, redact it before you share it.

Real exchangegenerated live with a coding agent
Student

I'm trying to run the first cell of the analysis notebook for my project and I keep getting this. I have no idea what it means.

ModuleNotFoundError: No module named 'pandas'

What do I do?

Agent

That error just means Python can't find pandas — a data library your notebook needs — because it isn't installed in your environment yet. Totally normal, and easy to fix.

In a new notebook cell, run this and then press Shift+Enter:

%pip install pandas

The %pip (instead of plain pip) makes sure it installs into the same place your notebook is running from, which avoids a common headache.

How to check it worked:

  • You should see a line ending in something like Successfully installed pandas-...
  • Now re-run your first cell — the ModuleNotFoundError should be gone.

If it still errors after that, tell me what the new message says and we'll take the next step together.

03 The agent gave me too much

A wall of text is not your fault and not the only option. You are allowed to constrain the assistant.

Shrink it to one step
That was too much. Give me only the next action, then stop. Do not explain extra background unless I ask.
Switch to tutor mode
Please switch to tutor mode. Ask me to report what I see after each step before giving the next step.
No assumed knowledge
I am new to this. Do not assume I know Git, Python, Bash, WSL, VS Code, or package managers. Use plain language and one step at a time.
Real exchangegenerated live with a coding agent
Student

That was way too much. I'm overwhelmed and I don't know which part to do first. Can you just give me ONE thing to do?

Agent

Here's the one thing — and only this one thing:

Open your terminal and type python --version, then hit Enter.

That's it. Don't worry about anything else from my earlier message yet.

You'll know it worked if you see something like Python 3.11.5 print out (any number is fine).

If instead you see an error like "command not found," that's totally okay too — it just tells us where to start.

Reply back with whatever shows up on your screen, and I'll give you the next single step from there. You've got this! 🙂

04 The agent wants to change things

Agents can edit files, delete files, install packages, force-push, or overwrite notebooks. Confident tone ≠ safe action.

🛟
The reversibility rule

Before you let an agent change files, delete things, install packages, force-push, overwrite notebooks, or touch data — ask what will change and whether it can be undone. Reversible first, always.

Before-I-act safety prompt
Before I do this, tell me:
1. What files, settings, or data this action may change.
2. Whether the action is reversible.
3. How I can inspect or back up the current state first.
4. What the safest smaller version of this action would be.
Real exchangegenerated live with a coding agent
Student

Another agent told me to run git checkout -- . and also pip freeze > requirements.txt to "fix my setup." Before I run anything: what will these actually change, and can I undo it if it goes wrong?

Agent

git checkout -- . and pip freeze > requirements.txt do two very different things, and one of them is the risky one.

git checkout -- .

  • What it changes: throws away all uncommitted edits to tracked files in your working directory, reverting them to the last commit.
  • Reversible? No. Discarded changes that were never committed are gone for good. (Untracked/new files aren't touched, but anything you edited-but-didn't-commit is.)
  • Inspect first: 
    git status        # see what would be lost
git stash         # safely tuck changes aside instead of deleting
    git stash is the smaller, reversible version — you can bring them back with git stash pop.

pip freeze > requirements.txt

  • What it changes: overwrites requirements.txt with the exact package versions in your current environment.
  • Reversible? Yes, if the file is tracked in git — git checkout requirements.txt restores it. Back it up first to be safe: 
    cp requirements.txt requirements.backup.txt

So: the pip command is low-stakes. The git checkout is the one to pause on. Run git status first, and if there's any work you care about, git stash instead of checkout.

05 I'm afraid I broke something

Recovery before perfection. The first move is never "fix it" — it's "look at it." Inspecting is always safe.

Inspect-first prompt
I think I may have broken something. Do not suggest fixes yet.

Please help me inspect the current state first. Tell me what information to collect, what commands or views are safe, and how to avoid making things worse.

Context:
[WHAT I WAS TRYING TO DO]

What changed:
[WHAT I THINK HAPPENED]

Safe things to look at before changing anything:

  • Look at the file diff — what actually changed.
  • Check Git status.
  • Open the website preview.
  • Compare against the last committed version.
  • Ask the agent to explain the diff before you accept it.
Real exchangegenerated live with a coding agent
Student

I think I broke everything. I was following commands an agent gave me to "clean up" my repo and now my edits to index.html seem to be GONE and git is showing a bunch of scary red text. Please tell me how to undo this!!

Agent

Don't worry, your edits are almost certainly recoverable, and the red text is just Git describing the current state, not an error. In Git, work that was ever committed is very hard to truly lose, and even uncommitted changes often leave traces we can check. Let's look before we touch anything.

Could you run these read-only commands (they only show information, they change nothing) and paste back the full output?

git status
git log --oneline -10
git stash list

A couple of quick definitions: git status shows your current files (the "red text" is usually just modified or untracked files), git log lists recent commits (saved snapshots), and git stash list shows work that may have been tucked away by that "clean up."

One question: had you saved your index.html edits with a commit, or were they unsaved when this happened? Either way, don't run any more agent commands for now. Once I see the output above, I can tell you exactly where your edits are and the safest way to bring them back.

06 I don't understand the answer

Silently nodding is the trap. Asking the agent to translate itself is a skill, not a weakness.

Translate to beginner language
Please translate your answer into beginner language. Define any technical term before using it.
Analogy + action
Explain this using an analogy and then give me the practical action I should take.
Essential vs background
Which parts of your answer are essential for me to do now, and which parts are background?

07 Help with GitHub

You do not need all of Git. You need five words and the courage to make a small change.

A repository is a project folder with history.
A commit is a saved checkpoint.
A branch is a separate line of work.
A diff shows what changed.
A pull request is a reviewable proposed change.
GitHub help prompt
I am working in a GitHub repository for a course. Please explain what I need to do in beginner language.

My goal:
[GOAL]

Current situation:
[WHAT I SEE]

Please tell me the safest way to make a small change, inspect the diff, and commit it.

08 Help with Python

Python here is a tool for making analyses reproducible — not a programming-identity test.

A Python file usually ends in .py.
A notebook usually ends in .ipynb.
A package is reusable code someone else wrote.
An environment controls which packages are available.
A plot or table should be reproducible from data and code.
Understand-this-code prompt
I am new to Python. I need to understand this file/notebook/script enough to use it safely.

Please explain:
1. What this code is trying to do.
2. What inputs it needs.
3. What outputs it creates.
4. What assumptions or units I should check.
5. One small change I can safely make to test my understanding.

Here is the code or file summary:
[PASTE CODE OR DESCRIPTION]

10 Turn a research task into an agent task

Agents are much better at tasks than at wishes. This is the bridge from setup to real research work.

Scope-a-task prompt
I want to use an AI agent to help with this research task:

[DESCRIBE TASK]

Please help me turn it into a well-scoped agent task. Include:
1. A concise task statement.
2. Context the agent needs.
3. Inputs and outputs.
4. Acceptance criteria.
5. Risks or things the agent might get wrong.
6. A smaller first version of the task.
Real exchangegenerated live with a coding agent
Student

I want to use the agent to help me analyze my survey data, but every time I just say "analyze my survey data" I get something useless. How do I turn this into a real task?

Agent

Make "analyze my survey data" into a real task

The fix is specificity. "Analyze my survey data" gives the agent no goal, no data shape, and no idea what "done" looks like — so it guesses. Here's a template you can fill in and hand over.

1. Task statement (one line)
"Summarize responses to my 12-question post-course survey and test whether reported confidence differs between undergrad and grad students."

2. Context the agent needs
What the survey is, who took it, how many responses, and what you actually want to learn. State the one or two questions that matter most.

3. Inputs & outputs

  • Input: survey.csv, one row per respondent. Note which columns are Likert (1–5), categorical, or free text.
  • Output: a short summary table + 2–3 plots, plus a paragraph of findings. Specify the file (results.md, figures as PNG).

4. Acceptance criteria

  • Every question summarized (n, mean/median, or category counts).
  • Missing data reported, not silently dropped.
  • Any statistical test names the method and assumptions.

5. Likely failure modes
Misreading Likert text as categories, dropping blanks silently, over-claiming significance from tiny groups, inventing columns. Tell it to ask before guessing.

6. Smaller first version
Start with: "Load the CSV, list every column with its type and a one-line summary, and flag data-quality issues." Once that's right, ask for the analysis.

11 Verify the agent's work

🔬
This is the most important section on the page

Agent output is a draft or a hypothesis. It is not verified research evidence until you check it. A pretty plot is not a result. Matplotlib can lie in high resolution.

Verification is not asking "does this look okay?" It is asking "how could this be wrong?" Some ways to check:

  • Run a test, or reproduce a simple case by hand.
  • Compare with known values, a spreadsheet, or a published paper.
  • Check units and dimensions.
  • Inspect a plot for impossible values.
  • Check citations manually.
  • Ask a second model to critique the result.
  • Ask the agent what would falsify its answer.
Verification-plan prompt
The agent produced this result:

[DESCRIBE OR PASTE RESULT]

Please help me design a verification plan. I want checks that could catch plausible errors, not just confirm the result. Include at least one simple sanity check and one stronger check.
Real exchangegenerated live with a coding agent
Student

An agent generated a plot of jet fuel burn versus cruise altitude for my project and it looks really clean and convincing. How do I actually know it's correct before I put it in my portfolio?

Agent

Treat the agent's plot as a hypothesis, not a verified result. Here's how I'd pressure-test it before it goes anywhere near your portfolio.

Quick sanity checks (catch the obvious):

  • Units & axes: Is fuel burn in sensible units (kg/hr? kg/nm?) and altitude in ft or km? Mislabeled axes are the #1 silent error.
  • Ranges: Do the numbers sit in a plausible band for your aircraft class? A narrow-body burning 200 kg/hr or 20,000 kg/hr should both make you suspicious.
  • Trend shape: Burn per distance generally drops with altitude up to a point, then flattens or rises. A perfectly straight line is a red flag.

One stronger check:

  • Reproduce a single point by hand. Pick one altitude, find the inputs the agent used, and recompute fuel burn yourself (or against a published value / textbook drag-polar example). If you can't recover the agent's number within a few percent, something's off in its model or assumptions.

Then ask the agent directly: "What assumptions, data, or equations would, if wrong, make this plot wrong? Show me the formula and inputs for the point at X altitude." If it can't tell you what would falsify the result, you don't yet have evidence — you have a nice-looking draft.

12 When to ask a human

This page does not pretend agents solve everything. Knowing when to stop is a skill the course is grading you on.

🧑‍🏫
Ask a TA or instructor when…

• The agent suggests deleting, overwriting, force-pushing, or exposing private data.
• You are stuck in a loop after two or three agent attempts.
• The task involves sensitive, proprietary, human-subject, export-controlled, or unpublished data.
• You do not understand the risk of a command.
• You cannot tell whether the output is scientifically or technically valid.
• You need help scoping a research task.

13 What not to paste into AI tools

🚫
Keep these out of public AI assistants

Passwords · API keys · private access tokens · unpublished or embargoed data · human-subject data · proprietary or export-controlled material · anything you would not put in a public GitHub repo. When in doubt, redact first or ask a human.

REF Beginner glossary

Plain-language definitions for the words that show up most. No shame in keeping this open in a tab.

Terminal
A text window where you type commands for the computer to run, one line at a time.
Command
A single typed instruction you run in a terminal (e.g. git status).
Repository (repo)
A project folder that also stores its full history of changes.
Commit
A saved checkpoint of your work, with a short message describing what changed.
Diff
A side-by-side view of exactly what changed between two versions.
Branch
A separate line of work so you can experiment without touching the main version.
Pull request (PR)
A proposed change others can review before it's merged in.
Python
A programming language widely used to make analyses reproducible.
Notebook
A document (.ipynb) that mixes code, results, and notes in runnable cells.
Package
Reusable code someone else wrote that you can install and use.
Environment
The set of packages and settings available to your code right now.
Agent
An AI assistant that can take actions — read files, run commands, make edits — not just chat.
Context
The information you give the agent to work with: your goal, files, data, and constraints.
Verification
Checking whether a result is actually correct, with tests designed to catch errors.
